Sample 1 is only a baseline. Total PPS uses only the general rule's packet delta divided by actual monotonic elapsed seconds. Mbps uses only its byte delta times 8 divided by elapsed seconds and 1,000,000. Protocol counters are never added to the total.

The capture observed 600 additional UDP packets and 16,800 additional UDP bytes. The general rule increased by exactly the same amounts, confirming that its interface matched this observed traffic. Two full intervals were approximately 10 UDP PPS; partial/burst intervals varied. The capture cannot establish that all packets came from one invocation of the provided Kali command: there were more than 100 packets and some intervals exceeded 10 PPS. No traffic was generated by NetShield or this diagnostic.

Timestamps are timezone-aware server receipt times, stored in UTC and displayed above in Baghdad time. Rates use the monotonic clock, independent of wall-clock adjustments. Router/server NTP synchronization was not independently audited. Counters are sequential API observations, not an atomic packet-level snapshot.

## Errors, invalid data, and ordering

The initial sandboxed connection was blocked locally with Windows socket error 10013. The authorized network-capable retry succeeded; the 13-sample capture completed without API errors or invalid samples.

The bounded collector validates missing/duplicate/conflicting rules and unsafe placement. It stops and reports an error on API failure rather than reusing stale samples. It reuses the existing rate calculator: malformed counters, decreasing counters, changed rule identity, nonpositive elapsed time, or gaps over 180 seconds produce no calculated rate and require a new valid baseline. Live counters were never deliberately reset to test these cases; automated tests cover them.
